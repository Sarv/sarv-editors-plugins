The plugin runs inside the editor with no window of its own. Your page talks to it with postMessage: you ask for the document, it answers with the content, you put that content wherever you want. Five steps, all in the page that embeds the editor.

1Load the plugin for this client

Add this to the config you hand to DocsAPI.DocEditor. The URL and guid below are this plugin's real ones, read off the running copy - copy the block as it stands. Clients that should not have the export simply do not get it.


        


        

            
2Add the target element

            
Anywhere in your page - this is where the document will land.

            
<div id="output"></div>

        


        

            
3Listen, and keep the sender

            
The plugin announces itself once it starts. Hold on to
               event.source - that is the only handle you can reply to.

            
const CHANNEL = "sarv-content-export";
let plugin = null;

window.addEventListener("message", (event) => {
  const data = event.data;
  if (!data || data.channel !== CHANNEL) return;

  if (data.type === "ready") {
    plugin = event.source;
    plugin.postMessage({ channel: CHANNEL, type: "ack" }, "*");
  }
});

        


        

            
4Ask for the document

            
Call this from your own Submit or Preview button. Leave
               format out to use whatever the Settings tab says.

            
Wait for ready first. The plugin starts after the document
               does, so onDocumentReady is too early - plugin is still
               null there. Gate on step 3 having run: enable your button in the
               ready branch, or queue the request and send it from there.

            
function requestContent(format) {         // "html" | "markdown" | omit
  plugin.postMessage(
    { channel: CHANNEL, type: "extract", requestId: "req-1", format },
    "*"
  );
}

        


        

            
5Inject the answer

            
The reply arrives in the same listener you wrote in step 3.
               data.content is the whole answer - every style is inline, so there is
               no stylesheet to place and nothing else to wire up. Keep it in a variable
               instead if you are posting it somewhere rather than showing it; ask for
               escape: "json" on the extract and it arrives ready
               to drop into a payload.

            
if (data.type === "result") {
  const box = document.getElementById("output");

  if (data.escape !== "none") {
    box.textContent = data.content;              // escaped - a payload, not markup
  } else if (data.format === "markdown") {
    box.textContent = data.content;              // raw Markdown
  } else {
    box.innerHTML = data.content;                // self-contained HTML
  }
}

if (data.type === "error") {
  console.error("export failed:", data.message);
}

        


        

            
+Open this window from your page

            
Optional - a Settings button in your own toolbar.

            
plugin.postMessage({ channel: CHANNEL, type: "openSettings" }, "*");

        


        

            
Every message, both ways

            

                
You sendWhat it does

                
ackConfirms you are listening. Stops the ready beacon.

                
extractReturns the document. Optional format, markup, escape, options, requestId.

                
getSettingsAnswers with the current settings.

                
setSettingsOverwrites settings from your page.

                
openSettingsOpens this window.

                
You receivePayload

                
readyguid, editor, settings - repeated once a second until you ack (60 tries, then it gives up)

                
resultrequestId, ok, format, escape, content, meta

                
errorrequestId, ok, message

                
settingssettings - also sent whenever they change here

            


            
What each field holds

            

                
FieldHolds

                
channelAlways "sarv-content-export". On every message, both ways - ignore anything without it.

                
requestIdWhatever you sent on the extract, handed straight back. It is how you match a reply to its request when more than one is in flight; the plugin never invents one.

                
oktrue on result, false on error. Checking data.type is equivalent.

                
formatWhich format you actually got: "html" or "markdown". It follows the Settings tab unless your extract overrode it for that one call.

                
markupOn extract only, and only for HTML: "clean" (default) for lean semantic CSS 2.1 markup, "full" for the editor's raw clipboard payload. See the Markup section on the Settings tab.

                
escapeHow content is escaped: "none" (default, a plain string), "json" (a JSON string literal, surrounding quotes included), "entities" (&lt;p&gt;). Send it on extract to override the setting for one call; it comes back on result so you always know what you are holding.

                
contentThe document. One string, sent whole - not chunked, no second message. HTML is self-contained: fonts, sizes, colours, alignment, table widths, image placement and the page box itself are all inline CSS 2.1 styles. Markdown is the raw text. If escape is not "none" this is the escaped form - decode it before rendering.

                
metaWhere the content came from and what page it came from: source (GetFileHTML or ConvertDocument), markup, plus pageWidth, pageHeight, marginLeft/Right/Top/Bottom in twips and fontFamily, fontHalfPt for the document default. Informational - you do not need any of it to render content. Absent geometry means the editor had no document to read it from.

                
messageOn error only: why the export failed, in one sentence.

                
editorOn ready only: which editor the plugin came up in (word, cell, slide). Only word can export.

                
settingsThe saved settings object: format, markup, escape, base64img, frame, htmlHeadings, demoteHeadings, renderHTMLTags. Send the same shape back with setSettings, or pass any subset as options on one extract to override it for that call only.

            

            
Every message carries
               channel: "sarv-content-export"; ignore anything that does not.
